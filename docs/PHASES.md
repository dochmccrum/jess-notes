## Phase 7 — performance + polish
- [ ] `tools/vaultgen` seeded generator; all benchmarks in DESIGN §18 wired to CI with thresholds; fix regressions; polish.
- [ ] Android cold start on a real mid-range phone, release build (target <500 ms launch → note visible; pre-warming / native splash if missed). Emulator debug build: 0.87–1.6 s.
- [ ] Native binary size: ~20 MB per Android ABI (LTO, `codegen-units = 1`, stripping; affects server and Linux builds too).
- [ ] Opening a note with 50 images takes 110–130 ms in Chromium on GitHub's runners (WebKit 40–60 ms there, 15–30 ms locally). The e2e check allows 200 ms on CI until this is understood.
- [ ] PDF first page at DPR 2: Playwright WebKit (Desktop Safari, DPR 2) takes 600–850 ms locally and 1.2–1.4 s on GitHub's runners (340–430 ms at DPR 1; Chromium at DPR 1 150–500 ms); SPEC wants <300 ms on desktop. Consider a DPR-1 first paint then a sharp re-render. The e2e check allows 2 s in WebKit until then.
- [x] Intermittent (about 1 in 3 local full runs in Playwright's Docker image, never yet on CI): pasting 50 images in Chromium crashes the page's service worker (CDP `Inspector.targetCrashed` on the `sw.js` target), and the test's evaluate fails with "Promise was collected" / "Execution context was destroyed". Passes when run alone. Investigate the `/_blob/` route under 50 concurrent requests. Two causes: the service worker opened a new IndexedDB connection for every `/_blob/` request and never closed one, and an awaited evaluate that spans the paste fails in Playwright even when the page is fine (DESIGN §22 item 62).
- [x] Web durability: keystrokes in the 30 ms coalescing window are lost if the page is killed before the worker commits them (the status no longer says "Synced" meanwhile, DESIGN §22 item 54). Fixed with an IndexedDB update journal that is replayed at init (item 61).
